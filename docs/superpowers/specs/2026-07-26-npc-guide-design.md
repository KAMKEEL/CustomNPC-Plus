# NPC 引路指令设计

日期：2026-07-26

## 目标

给玩家一条指令 `/guide <NPC名>`，在世界里画出一条通往该 NPC 的可视化路径——死亡空间（Dead Space）Locator 那种从脚下发出、贴地蜿蜒、能量沿线流动的发光带，终点是一个菱形标记。玩家自己走，指令不接管移动。

面向普通玩家（权限级 0），不是管理工具。

## 非目标

- 不做自动寻路带走。接管玩家移动在多人服上等同作弊，且要处理卡住/重试/传送等大量边界情况。
- 不做 NPC 全局位置索引。CNPC+ 的 NPC 存在区块里，没有全局索引；建一份需要监听 NPC 生成/移除并持久化，是另一个量级的工程。本设计接受"目标区块未加载则找不到"的限制。
- 不做跨维度引路。

## 参考实现

GTButler（`D:\MC\MODS_DEV\GTButler`）的三个类是本设计的基础：

- `com.gtbutler.movement.Pathfinder` — 自研 A*，本设计整体移植。
- `com.gtbutler.movement.PathRenderer` — `RenderWorldLastEvent` 里画路径，本设计参考它的 GL 状态管理（`try/finally` 复原）与坐标变换，视觉表现完全重做。
- `com.gtbutler.command.CommandGoto` — 参考它的异常兜底写法。

### 关键发现

`Pathfinder.Search` 在预算用完时**不返回"找不到"，而是返回搜索过程中离终点最近的那条路**（`Search.finish()`，配合 `fallbackScore()` 把横向偏差权重放大 100 倍）。

这个性质直接实现了"分段引路"：目标在 800 格外时，把真实坐标当终点、给有限预算跑一次，A* 会朝目标方向探到已加载区块的边界然后返回那条路。玩家沿路走一段、起点前移、再算一段。**不需要构造伪目标点。**

同时，客户端未加载区块的 `World.getBlock()` 返回空气，`isSolidFloor()` 判定为假，A* 走不进去，会自然停在加载边界——不会画出穿过未知地形的假路。

## 架构

### 服务端

**`kamkeel.npcs.command.GuideCommand`**（独立注册，非 `/kam` 子命令）

在 [CustomNpcs.java:449](../../../src/main/java/noppes/npcs/CustomNpcs.java#L449) 附近的 `registerServerCommand` 处注册。继承 `CommandBase`，`getRequiredPermissionLevel()` 返回 0，`canCommandSenderUseCommand()` 返回 true。

职责：按名字在玩家当前维度的 `loadedEntityList` 里找 `EntityNPCInterface`，把结果通过 `GuideTargetPacket` 发回该玩家客户端。无状态——服务端不记录谁在引路。

### 客户端（新包 `noppes.npcs.client.guide`）

| 类 | 职责 |
|---|---|
| `GuidePathfinder` | 从 GTButler 移植的 A*，只保留分帧的 `Search` |
| `GuideSession` | 持有当前目标、驱动分帧搜索、维护当前显示的路径、处理结束条件 |
| `GuideRenderer` | `RenderWorldLastEvent` 里画发光带 + 菱形标记 |
| `GuideRenderConfig` | 所有视觉常量（阈值、颜色、宽度、脉冲参数）集中在此，便于调手感 |

`GuideSession` 是单例，同时只允许一个引路目标；新指令覆盖旧的。在 `ClientProxy` 里注册它的 tick 回调与 `GuideRenderer` 的渲染回调（参考 [ClientProxy.java:376](../../../src/main/java/noppes/npcs/client/ClientProxy.java#L376) 一带现有的注册写法）。

### 网络

沿用项目现有的 `kamkeel.npcs.network` 包体系新增两个包：

**`GuideQueryPacket`（C→S）**

字段：NPC 名、已锁定的目标 UUID（可为空）。

由指令触发一次；之后 `GuideSession` 每 5 秒自动发一次，刷新超出客户端加载范围的目标坐标。带 UUID 是为了刷新时锁死同一个 NPC——否则玩家走近另一个同名 NPC 时目标会被悄悄换掉。

**`GuideTargetPacket`（S→C）**

字段：动作（`START` / `STOP` / `STATUS`）、是否找到、维度 ID、目标 UUID、坐标（x/y/z）、显示名、同名数量。

引路状态只存在于客户端，服务端不知道玩家当前在引路去哪。所以 `/guide stop` 与无参的 `/guide` 都由服务端转成一个控制包发回客户端，由客户端自己执行并打印：

| 指令 | 服务端发出 | 客户端行为 |
|---|---|---|
| `/guide <名>` | `START` + 查找结果 | 找到则开始引路；没找到则打印对应提示 |
| `/guide stop` | `STOP` | 结束当前引路；本来就没在引路则打印"当前没有正在进行的引路" |
| `/guide` | `STATUS` | 打印当前目标与直线距离；无目标则打印用法 |

## 寻路

### 移植改动

`GuidePathfinder` 相对 GTButler `Pathfinder` 的三处改动：

1. **删掉两个同步 `findPath()` 重载。** 引路只用分帧的 `Search`；同步版本会卡主线程。
2. **改预算**：`MAX_NODES = 30000`、总时限 3 秒。不像 `/goto` 那样不限时——引路是每秒重算的常驻功能，必须有硬上限兜底。
3. **终点取 NPC 脚下那格**（`floor(posX)`, `floor(posY)`, `floor(posZ)`）。

其余照搬：判断能不能站、平移/斜移/爬降 1 格、斜移不穿墙角、熔岩与火焰视为不可通行。

NPC 站在半砖或楼梯上时，其脚下格不满足 `isStandable()`，A* 到不了终点，于是走 fallback 返回"搜到的最接近的点"。效果上路会走到 NPC 跟前停住，可以接受，不额外处理。

### 刷新节奏

- 每 **20 tick（1 秒）**起一次新 `Search`，起点为玩家当前脚下格。
- 每 tick 调 `search.step(System.nanoTime() + 20_000_000L)` 推进一小段。
- **新路径算完之前，继续显示旧路径**，不清空——否则每秒闪一下。
- 上一次搜索没算完就到了下一个刷新点：直接丢弃重来，起点已变，旧结果无用。

### 目标坐标的两种来源

| 情况 | 坐标来源 |
|---|---|
| 目标在客户端加载范围内 | 按 UUID 在 `theWorld.loadedEntityList` 里找到实体，用其实时位置。NPC 巡逻走动时路径跟着变。 |
| 不在范围内 | 用服务端下发的静态坐标，并每 5 秒发一次 `GuideQueryPacket` 刷新。跟丢窗口最多 5 秒。 |

## 渲染

### 曲线生成

A* 输出的是格子折线，直角很硬。先做 **2 轮 Chaikin 切角细分**（每轮把每条边替换成 1/4 和 3/4 两个点），折线变圆滑，爬台阶时的 y 跳变也一并被磨平。纯数组运算，开销可忽略。

**起点裁剪**：在细分后的曲线上找离玩家最近的点，从该点开始画，走过的部分丢弃。这样带子的头始终贴在玩家脚下。

### 发光带

沿细分曲线生成 `GL_QUAD_STRIP`：每点算出垂直于前进方向的水平向量，向两侧各撑出半宽；y 取路径点 + 0.05 防 z-fighting。

画两层：

| 层 | 半宽（格） | 颜色 | alpha 系数 |
|---|---|---|---|
| 外发光 | 0.30 | `(80, 170, 255)` | ×0.35 |
| 芯 | 0.10 | `(200, 240, 255)` | ×1.0 |

GL 状态：加法混合 `GL_SRC_ALPHA, GL_ONE`（固定管线做发光感的标准做法），关 `GL_DEPTH_TEST`（穿墙全亮）、关 `GL_TEXTURE_2D`、关 `GL_CULL_FACE`、`glDepthMask(false)`。

**用 `try/finally` 保证 GL 状态复原。** 渲染回调里半途抛出的异常会让后续所有渲染都花掉，这一点比 `try/catch` 更重要。

### 每顶点 alpha

```
alpha = 距离衰减 × 脉冲

距离衰减（d = 该顶点到玩家的三维距离，单位：格）：
    d ≤ 15        → 1.0
    15 < d < 20   → (20 - d) / 5
    d ≥ 20        → 0，该段跳过不画

脉冲：
    0.65 + 0.35 × sin(s × 0.35 − t × 0.15)
    s = 沿曲线的累计弧长
    t = worldTime + partialTicks
```

`s` 参与相位，波沿线往目标方向跑；`t` 是连续量，逐帧平滑不跳变。默认参数约为每 18 格一个波、每秒前进 3 格。

两者相乘即为目标效果：脚下实、远处淡出、玩家前进时前方线段依次浮现，同时能量始终在流动。

### 菱形终点标记

Billboard 四边形（按 `RenderManager` 的 `playerViewY` / `playerViewX` 反向旋转，始终正对镜头），旋转 45° 成菱形，边长约 0.6 格，画在 NPC 眼睛高度上方 0.5 格。同样双层（外发光 + 亮芯），外加一圈线框。缓慢自转 + 呼吸，复用同一个 `t`。

alpha 走另一条曲线（`d` = 玩家到目标的距离）：

```
d ≥ 15       → 0，不画
5 < d < 15   → (15 − d) / 10
d ≤ 5        → 1.0
```

## 指令 UX

```
/guide <NPC名>   开始引路
/guide stop      停止
/guide           显示当前引路目标与直线距离；无目标则打印用法
```

别名：`/yl`。

`stop` 与无参两种形式的实际处理都在客户端，服务端只负责转成控制包发回——见上文「网络」一节。

**Tab 补全**：第一个参数补全当前维度已加载的 NPC 名字（去重）。

### 名字匹配

逐级放宽：

1. 精确匹配
2. 忽略大小写
3. 剥掉颜色代码后的子串匹配

同一级命中多个则取离玩家最近的，并提示：`找到 3 个『铁匠』，已选最近的（38 格）`。

### 提示文案

| 情况 | 文案 |
|---|---|
| 当前维度找不到，其它维度有同名 | `『XXX』在下界，无法跨维度引路` |
| 完全找不到 | `附近没有叫『XXX』的 NPC（它所在的区块可能没有加载）` |
| 抵达 | `已抵达『XXX』` |
| 跟丢 | `跟丢了『XXX』` |

### 生命周期结束条件

1. 玩家距目标 ≤3 格 → 提示抵达并结束
2. `/guide stop`
3. 玩家切换维度
4. 连续 3 次刷新（15 秒）服务端都报找不到 → 提示跟丢并结束
5. 退出世界（客户端状态，自然清空）

同时只允许一个引路目标，再发一次指令直接覆盖。

## 错误处理

三处入口各包一层异常兜底——1.7.10 里这三个地方漏出去的异常都会直接崩游戏：

| 位置 | 处理 |
|---|---|
| `GuideCommand.processCommand` | `try/catch Throwable`，打日志 + 聊天栏报"内部错误（详情见日志）" |
| `GuideSession` tick 回调 | `try/catch Throwable`，打日志并结束当前引路（避免每 tick 刷屏） |
| `GuideRenderer` 渲染回调 | `try/catch Throwable` 打日志，**外加 `try/finally` 复原 GL 状态** |

## 已知限制

- **目标 NPC 所在区块未加载时，服务端也找不到它。** 多人服主城常驻加载无影响；单人跑远后会报"附近没有叫 XXX 的 NPC"。
- 不支持跨维度。
- 路径不考虑挖方块、放方块、大跳、连续下坠——与 GTButler 的 A* 能力一致。地形需要这些手段才能通过时，路会停在能走到的最远处。
- 远距离（>20 格）时屏幕上不显示任何引导元素，唯一的信息是脚下那 20 格的线朝哪拐。这是刻意的设计取舍。

## 测试策略

**可单测的部分**（纯函数，不依赖 Minecraft 运行时）：

- Chaikin 细分：给定折线，验证输出点数与端点保持。
- 距离衰减公式：验证 15/17.5/20 三个点的取值与分段连续性。
- 菱形 alpha 公式：验证 5/10/15 三个点。
- 累计弧长计算。
- 名字匹配的逐级放宽逻辑：给定名字列表与查询串，验证选中项与同名计数。

**需要人工验证的部分**：A* 移植后的实际寻路质量、发光带的视觉手感、脉冲频率、加法混合在不同亮度背景下的观感。这些没法自动化，在 `run-dev-client` 里目视确认。
